# AI 工作台 UI 设计规范

## 0. 适用范围

- 适用于 `web/src` 下的管理页、弹窗、抽屉、对话页与共享组件。
- 共享组件一律从 `@/components/ui` 导入；`ConfirmDialog` 从 `@/components/ConfirmDialog` 导入。
- 页面不得复制本文已有的样式与交互；新增交互模式先补规范，再落页面。
- 暗色主题为主，亮色主题必须同步验证；颜色、状态、间距一律走 token 与共享组件。

---

## 1. 设计原则

1. **信息密度分层**：列表与表格保持高密度扫读；配置与编辑一次只呈现一个任务区，禁止在一屏堆叠多个大型编辑区或长列表。
2. **一个页面只有一张筛选卡**：搜索、筛选胶囊、已生效条件都在同一张 `FilterBar` 里，不散落成多行工具栏。
3. **状态用颜色说话**：状态胶囊固定 5 种语义色，同一状态在全站不换颜色。
4. **卡片不是装饰**：卡片只用于分组和可点击容器；表格行不再套卡片。
5. **交互可撤销**：任何筛选条件都能单击移除，并提供「清除全部」。
6. **暗/亮双主题**：新样式沿用现有 `html.light` 覆盖层，不新增固定深色背景。

## 2. 页面骨架

标准列表页自上而下四段，间距固定：

```text
PageHeader            标题 / 副标题 / 主操作
FilterBar             搜索 + 筛选胶囊（+ 第二行已生效条件）
MetricCard 网格        可选；仅统计类页面使用
TableCard / 卡片网格    数据区
TablePager            分页（客户端分页时才需要）
```

### 2.1 PageHeader

- 标题：`text-[15px] font-semibold tracking-tight`；副标题：`text-[11.5px] text-zinc-500`。
- 主操作放右侧，按钮统一 `size="sm"`；破坏性操作（批量删除）只在有选中项时出现。
- 页头由 `PageHeader` 统一，页面不再自己写 `h1`。
- 同一页头最多 1 个 primary；次要动作使用 `RowAction`（28px）。
- 页头 `extra` 全站不用；视图内检索框放在内容区顶部的 `FilterBar` 里。

### 2.2 FilterBar

- 卡片：`rounded-xl border border-zinc-800/60 bg-zinc-900/40`；页面外层给 `mx-6 mt-3`。
- 第一行：搜索框默认 `flex-1 min-w-[15rem]`，其余为筛选胶囊。
- 第二行（`footer`）：自定义时间、已生效条件、清除全部。
- 筛选条件生效时：胶囊描边与文字变 indigo，并出现右上角清除按钮。
- 服务端分页列表的搜索防抖统一 250ms：`load` 的 `useCallback` 依赖带搜索词，effect 内 `window.setTimeout(…, 250)`，不另设 `debouncedQuery` 状态。

### 2.3 MetricCard

- 网格：`grid grid-cols-2 gap-2 sm:grid-cols-3 xl:grid-cols-6`，仅统计页使用。
- 内容：18px 图标块 + 11px 标签 + 19px 数值 + 10px 注脚；需要占比时加 2px 进度条。
- 失败率、错误数等异常指标用 `danger`；工具/技能调用用 `ok` / `accent`。
- 传入 `onClick` 后整卡变为筛选入口（`aria-pressed` + 高亮描边），用于审批状态、工具风险这类固定枚举。

### 2.4 TableCard

- 表格必须放进 `TableCard`，由它负责圆角、边框和滚动容器。
- 表头：`text-[11px] text-zinc-500`，单元格 `px-3 py-2`，不加全部大写。
- 行：两行结构。第一行主信息（12.5px，失败时红色）；第二行元信息（10px，会话短链 / 助理 / 模型 / 时间）。
- 分组表（工具、技能）：分组行 `bg-zinc-950/50`，可折叠，组内内容使用 `pl-8` 缩进。
- 有分页时通过 `footer={<TablePager .../>}` 传入，分页条与表体共用边框。

### 2.4.1 列表列宽

分页列表的列宽统一走 `COL` 档位（`@/components/ui`），页面不手写 `w-[…rem]`。

- 表格类名用 `tableLayout(最小宽度rem)`：固定布局 + 最小宽度，窄屏由 `TableCard` 横向滚动。
- `<colgroup>` 按列的语义取档位：

| 档位 | 宽度 | 用于 |
| --- | --- | --- |
| `COL.main` | 剩余宽度 | 名称、标题、描述等主内容列 |
| `COL.id` | `13rem` | ID、key、版本号 |
| `COL.tag` | `7rem` | 状态、类别、数量胶囊 |
| `COL.person` | `13rem` | 邮箱、操作者、触发人 |
| `COL.time` | `11rem` | 完整日期时间 |
| `COL.detail` | `12rem` | 路径、URL、动作名 |
| `COL.actions` | `13rem` | 带文字的行内操作 |
| `COL.actionsNarrow` | `8rem` | 一到两个短文字操作 |
| `COL.actionsIcon` | `5.5rem` | 一到两个纯图标操作 |
| `COL.actionsIconWide` | `9.5rem` | 三到四个纯图标操作 |
| `COL.index` | `3rem` | 序号列 |
| `COL.select` | `2.5rem` | 勾选列 |
| `COL.selectExpand` | `5rem` | 勾选 + 展开箭头列 |
| `COL.handle` | `1.5rem` | 拖拽把手、展开箭头列 |

- 主内容列必须配 `table-fixed` 吃满剩余宽度；单元格内文字用 `truncate` + `title` 兜底。
- 同一类信息在不同页面使用同一档位。

### 2.4.2 排序与时间

- 分页列表默认只开放时间列排序；诊断类页面可额外开放耗时等数值列，状态、名称等纯业务字段列不出现排序箭头。
- 每个分页列表至少提供一个时间列排序入口；页面没有时间列时补「创建时间」「最近同步」等时间列，不能整页无排序。
- 客户端分页与全量加载列表同样按时间排序，空值始终排在最后。
- 可排序列统一用共享 `SortableHead` / `SortButton`：未激活显示双向箭头，激活后显示当前方向；激活列的箭头用 `text-indigo-300`、标签用 `text-zinc-200`，`aria-sort` 挂在 `<th>` 上。
- 时间列默认按 `desc` 最新在前；数值列切过去默认按 `desc` 最大值在前，空值始终排在最后。
- 切换排序回到第 1 页。
- 自定义时间范围选中后必须展开起止时间输入，并在条件胶囊里回显实际起止时间，不能只显示「自定义」。
- 列表时间统一使用 `fullDateTime`，不使用「xx 分钟前」相对时间。

### 2.5 详情弹窗

- 沿用 Trace 详情的「诊断报告」结构：头部状态 + 主指标、分段标题、键值网格、可复制代码块。
- 弹窗标题只放对象名；状态、耗时等上下文放正文头部，不塞进标题。
- 详情弹窗只承载短摘要；超过一个视口仍无法收敛的内容改为详情页或抽屉。

### 2.6 详情入口

**列表 / 卡片行一律不整体可点；进详情只点对象名。**

| 规则 | 说明 |
| --- | --- |
| 入口位置 | 对象名渲染成 `<button type="button">`，`.truncate` + `hover:text-indigo-300`；卡片本身不带 `onClick`、不带 `cursor-pointer` |
| 行整体不响应点击 | `<tr>` / `<Card>` 不挂 `onClick`；行内其他可点元素不再需要 `stopPropagation` |
| 不设冗余「详情」按钮 | 对象名已是入口时，行末不再额外放「详情 / 查看」按钮 |
| 行内动作只放真正的动作 | `编辑` / `删除` / `运行` / `导出` 这类动作保留；纯跳转详情的按钮去掉 |
| 跳转与弹窗同源 | 跳转详情页的行同样把名称做成唯一可点目标 |

### 2.7 空状态与错误

- 空状态统一用 `EmptyStateCard`，页面不自写空状态卡。
- 错误提示使用统一 alert 样式，文案不溢出；不用 `window.alert`。
- 不需要用户决策的成功/失败反馈用 `Toast`；需要决策的错误用 `ConfirmDialog` 或 `Modal` 行内错误。

## 3. 交互方式与信息密度

### 3.1 按内容关系选择容器

| 内容关系 | 使用方式 | 适用 | 不适用 |
| --- | --- | --- | --- |
| 互不依赖的并列配置 | `Tabs`（共享组件） | 助理编辑、设置分组 | 有先后依赖的步骤 |
| 有先后依赖、需逐步校验 | Steps / 向导 | 创建向导、导入流程 | 编辑已有对象（用户可能只改一项） |
| 可选、低频或长集合 | 折叠区 | 文档级范围、试检索、能力分组、示例 | 主任务本身 |
| 大量同类记录 | 独立列表页 + `FilterBar` + `TableCard` | 文档、会话、运行记录 | 弹窗内嵌长表格 |
| 短确认 / 短表单 | `Modal` | 重命名、删除确认、单段表单 | 多分区配置、长编辑器 |
| 只读长内容 | 详情页 / 抽屉 + `DetailSection` | 运行详情、Trace、长日志 | 列表弹窗 |

选择顺序：先判断内容是否并列、是否有先后依赖、是否需要长期浏览，再决定 Tabs、Steps、折叠、独立页或弹窗；不得先选容器再往里塞内容。

### 3.2 密度约束

- **一个视图只做一个主任务**：同一 Tab、Step 或弹窗面板内，不得同时出现两个及以上大型编辑器、长列表或目录树。
- **首屏可见**：以 1280×900 为验收口径，默认状态下主任务区与主操作必须在首屏可见；需要滚动才能找到保存/下一步即不合格。
- **默认收起**：可选、低频、长集合默认折叠；折叠标题必须给出名称 + 数量或当前状态。
- **长集合限高**：目录树、文档列表、工具清单等长集合必须设置 `max-height` + `overflow-y-auto`，不得把弹窗整体撑高。
- **默认状态最多一个二级滚动区**：用户主动展开的补充区不计；默认状态下出现两个以上滚动区时必须拆分或折叠。
- **弹窗只做短任务**：`Modal` 最大 `size="xl"`；分区/折叠后仍超过一个视口的内容，改用独立页面或抽屉，不靠加高弹窗解决。
- **禁止嵌套 Tabs**：一个配置区只使用一层 Tabs；Tabs 内需要再分类时用折叠区或分段控件。
- **禁止横向滚动的表单**：窄屏下表单改为单列；不允许用横向滚动查看字段。

### 3.3 Tabs

- 只用于并列、互不依赖的配置域；有先后依赖的流程用 Steps，不把步骤伪装成 Tabs。
- 标签数量 2–6 个；每个标签是一个独立主题，标签名不超过 6 个汉字。
- 必须使用共享 `Tabs` / `TabsList` / `TabsTrigger` / `TabsContent`，不手写 tab 样式。
- 切换 Tab 不得丢失草稿；面板使用 `keepMounted` 保留未提交输入。
- 必填项缺失时，对应 Tab 标签显示状态点；底部保存区同时给出「还需填写：…」的可定位提示。
- 页级视图切换（如文档 / 语义检索）同样使用共享 Tabs，放在 `PageHeader navigation`；筛选条件不得做成 Tab。

### 3.4 折叠区

- 折叠标题必须是可聚焦按钮，带 `aria-expanded`；展开/收起图标使用 11px chevron，展开时旋转 90°。
- 默认收起；以下情况自动展开：
  - 该区已有选中项；
  - 该区存在校验错误；
  - 用户刚完成与该区相关的操作。
- 折叠标题必须显示数量或状态，例如「按文档精确选择 · 已选 3 篇」「内置工具 (10)」。
- 折叠区内不得再嵌套同级的折叠区；单个条目的详情展开（如技能工具清单、MCP 工具清单、目录树节点）除外。

### 3.5 可搜索选择器

工具、技能、MCP Server、目录、文档这类候选集合必须提供搜索，搜索不是可选项。

- 选择器搜索放在面板头部右侧，宽度 13.5–14.5rem，不独占整行；窄屏折行后占满可用宽度。
- 搜索范围覆盖用户可见名称、稳定标识、路径；技能还要匹配其声明的工具，MCP Server 还要匹配其工具名与描述。
- 输入搜索词后，用扁平结果列表替换原树/分组，避免用户逐层展开；结果行必须保留勾选、屏蔽与「随上级」继承态。
- 搜索结果显示匹配数量；无结果时给出明确文案，不显示空分组。
- 清空搜索恢复原浏览结构；搜索过程不得丢失已选项，也不得改变已选范围。
- 已选项始终在预览或已选清单中可见，不因当前搜索结果不包含它而消失。
- 长选择器采用「左侧候选 + 右侧预览」双栏：左栏负责搜索与勾选，右栏常驻总量、来源拆分与异常说明；两栏各自限高滚动，不把弹窗整体撑高。

### 3.6 弹窗中的配置编辑器

- 内容互不依赖的编辑用 Tabs；从零创建、有先后依赖的流程用 Steps，不把向导伪装成 Tabs。
- 向导每一步只校验本步必填项；当前步未完成时「下一步」禁用，并给出本步缺失提示；最后一步才出现创建按钮。
- 标识类字段必须按后端同一正则做前端校验，帮助文案写明允许字符、长度与保留名；格式错误与未填写分别提示。
- 编辑弹窗底部操作条固定：左侧放缺失必填项提示，右侧放取消 / 保存；保存按钮在必填项缺失或范围校验失败时禁用。
- 字段标签使用 11px 字号；单控件用 `Field`，复合控件（按钮组、列表、树、多选）用 `FieldGroup`，不用 `<label>` 包裹整组。
- 表单默认最多两列；只有短字段（名称、数字、下拉）可并排三列，长文本、树、列表必须通栏。

### 3.7 助理编辑器的固定分区

助理新建与编辑共用 5 个分区，不得继续往单个分区里堆叠：

- **新建**：5 步向导（基础 → 人设 → 知识范围 → 能力绑定 → 委托与运行），逐步校验后创建。
- **编辑**：5 个 Tabs（同一组分区），用户可直接改任意一项后保存。

| 分区 | 主任务 | 默认展开 | 默认收起 |
| --- | --- | --- | --- |
| 基础 | 标识、显示名称、描述、何时使用 | 全部字段 | 无 |
| 人设 | 模板、系统提示、关键提醒、输出格式、示例 | 系统提示与模板 | 示例列表（有示例时展开） |
| 知识范围 | 左侧目录树与搜索，右侧已选范围、命中预览与试检索 | 目录树、命中预览、已选清单 | 按文档精确选择 |
| 能力绑定 | 左侧能力目录与搜索，右侧装配预览与异常说明 | 内置工具、搜索框、装配预览 | 技能明细、MCP 工具明细 |
| 委托与运行 | 子助理、权限、模型、最大轮数 | 全部字段 | 无 |

- 知识范围固定两栏：左栏顶部放目录标题与内嵌搜索，下面是可滚动的目录树或扁平搜索结果；右栏常驻已选目录/文档胶囊、命中篇数、目录拆分和试检索。目录项保留「随上级」「部分」状态，已选胶囊可直接移除。
- 能力绑定固定两栏：左栏顶部放能力标题与内嵌搜索，下面是内置工具/技能/MCP 分组；右栏常驻进上下文数量、工具来源、已选能力与口径异常。分组有选中项或搜索命中时自动展开，清空搜索恢复原展开状态。
- 两栏高度固定为 26rem 左右，左右栏独立滚动；右侧预览不得因搜索结果变化而隐藏已选项。
- 搜索框不得独占整行，统一放在面板头部右侧。
- 保存区必须提示跨分区缺失的必填项，不允许只把按钮置灰而不说明原因。

### 3.8 助理卡片

**设计目标**：不打开详情，也能回答「它是谁、能做什么、有哪些硬约束、怎么开始用」。

**信息层级**（自上而下）：

1. 身份行：头像、显示名称、来源胶囊、只读标记与编辑/删除；只有名称进入详情。
2. 身份元信息：Agent 标识与显式配置的模型；未配置模型时只显示标识，不重复「默认模型」。
3. 描述：固定两行，保持同排卡片底栏对齐。
4. 关键提醒：运行时真正注入的约束，最多两行；没有则不占位。
5. 能力摘要：工具 / 技能 / 委托三格等分统计；继承态写「全部」，空态写「无」。
6. 知识范围：单独一行，目录名优先，文档只报篇数。
7. 底栏：输出格式/示例数与主操作「使用此助理」。

**设计取舍**：

- 卡片本身不可点，只有名称进入详情，避免点空白或选文字时误跳转，也避免与编辑、删除、使用按钮抢事件。
- 关键提醒比「何时使用」更影响使用判断，所以前者上卡片、后者留在详情。
- 描述和提醒都限两行，保证网格中同排卡片高度稳定、底栏对齐，列表可横向扫读。
- 摘要用「全部 / 无」表达继承和空态，避免 0 被误读为「没有能力」。
- 模型是次要信息：只有显式覆盖默认模型时才显示，避免每张卡重复「默认模型」。
- 主操作固定右下，破坏性操作只保留图标放右上，降低误触。

### 3.9 MCP 服务卡片

MCP 服务保持整行卡片与内联展开，不套用助理的网格卡；重点是压缩状态信息、把连接异常放到卡片上。

- 身份行：展开箭头、服务图标、名称、连接状态；免审和停用紧邻名称。图标底色随状态变化（正常 indigo、异常 rose、停用 zinc）。
- 元信息：`transport · endpoint` 单行，端点超长截断并用 tooltip 显示全文。
- 摘要行：工具数 · 审批口径 · 索引状态，用分隔点串联，不再堆一排彩色胶囊；免审服务省略审批口径，避免与「免审」重复。
- 异常：连接错误或测试失败共用一条错误横幅，不在标题行重复状态胶囊。
- 操作：测试连接保留文字按钮（含 loading），编辑、删除收为 `RowActionIcon` 并使用 tooltip；非 admin 禁用。
- 展开区：先给「工具清单 + 数量」标题，再列工具；工具仍可展开参数表并试跑。
- 工具缓存损坏时摘要行显示「工具缓存异常」，展开区给出重新拉取的指引。

### 4.1 状态语义

| tone | 颜色 | 适用 |
| --- | --- | --- |
| `ok` | 绿 | 成功、已执行、已批准、安全、活跃 |
| `warn` | 琥珀 | 待处理、需审批、已暂停、变更类技能 |
| `danger` | 红 | 失败、危险操作、拒绝后异常 |
| `info` | 蓝 | 进行中、置顶、运行态 |
| `neutral` | 灰 | 已拒绝、已过期、归档等终态 |

状态胶囊统一用 `StatusPill`，圆点 + 文案；进行中可加 `pulse`。状态一律用 `StatusPill`，不写裸文字 + 硬编码色值；角色等分类信息用 `Chip`。

| `Field` / `FieldGroup` | 单控件字段 / 复合控件字段 |

### 5.1 行内操作按钮

列表 / 表格行末、卡片右上角的操作一律用 `RowAction` 与 `RowActionIcon`，页面不手写按钮 className。

| 组件 | 规格 | 用途 |
| --- | --- | --- |
| `RowAction` | `h-7`、`px-2`、`gap-1`、`text-[11px]`、图标 12px、`outline` 表面 | 带文案的动作：批准 / 拒绝 / 运行 / 设为默认 |
| `RowActionIcon` | `h-7 w-7`、图标 13px、无边框 `subtle`、hover 底色 | 纯图标动作：编辑 / 删除 / 置顶 / 归档 / 导出 / 复制 |

- 语义色由 `tone` 控制：`neutral`（默认）、`positive`（`text-ok`）、`danger`（红色文字 + hover 红色底）。
- 危险动作只改颜色，不改尺寸与表面。
- 同一行的图标动作间距 `gap-0.5`，文字动作间距 `gap-1.5`。
- 操作组同时含文字动作时保持完整对比度，不要给整组叠加 `opacity-60`——文字动作被压暗后会被误读为禁用。
- 卡片级主操作可保留 indigo 强调色，但高度、内边距、字号必须与 `RowAction` 对齐（`h-7 px-2 text-[11px]`）。

### 5.2 Field 与 FieldGroup

- 单控件字段用 `Field`：标签 11px，必填项带 `*`。
- 复合控件（按钮组、列表、树、多选）用 `FieldGroup`：只渲染分组标题，不用 `<label>` 包裹。
- 用 `<label>` 包裹复合控件会把全部子文本并进第一个控件的可访问名，读屏与 Testing Library 都无法取到唯一目标。

## 6. 验收清单

- [ ] 页头使用 `PageHeader`，标题/副标题字号符合规范。
- [ ] 搜索与筛选收进一张 `FilterBar`，没有残留 `border-b` 工具条。
- [ ] 搜索框有清空按钮；任一筛选（含关键字）生效时显示「清除全部」，并一次清空所有条件。
- [ ] 列表使用 `TableCard` 或统一 `Card`，没有页面自写圆角/边框。
- [ ] 表头 11px、单元格 `px-3 py-2`，行内最多两层信息。
- [ ] 状态统一用 `StatusPill`，颜色符合语义表。
- [ ] 页头次要动作是 `RowAction`、主操作是 `primary size="sm"`，同一页头最多 1 个 primary。
- [ ] 行内操作只用 `RowAction` / `RowActionIcon`，没有手写 `h-7 px-2` 或 `p-1` 按钮。
- [ ] 空状态、错误提示使用统一卡片样式，错误文案不溢出。
- [ ] 有分页时使用 `TablePager`，区间文案为 `起-止 / 共 N 条`。
- [ ] 分页列表默认只开放时间列排序；可观测等诊断页额外开放耗时列，其余业务列不出现排序箭头。
- [ ] 每个分页列表至少有一个时间列排序入口，客户端分页列表也支持切换方向，空值排最后。
- [ ] 可排序表头用 `SortableHead` / `SortButton`，激活列有紫色箭头反馈，`aria-sort` 标在 `<th>`，切换排序回到第 1 页。
- [ ] 自定义时间范围展开起止输入，条件胶囊回显实际起止时间。
- [ ] 列表时间统一 `fullDateTime`，不使用「xx 分钟前」相对时间。
- [ ] 默认状态一屏只展示一个主任务区；可选长内容已折叠。
- [ ] 长列表/目录树已限高滚动；默认状态最多一个二级滚动区。
- [ ] Tab / Step 数量不超过 6 个，没有嵌套 Tabs。
- [ ] 从零创建使用 Steps 并逐步校验，编辑并列配置使用 Tabs。
- [ ] 工具 / 技能 / MCP / 目录 / 文档选择器提供搜索，搜索结果可直接勾选。
- [ ] 能力绑定与知识范围为左右双栏；搜索在左栏面板头部，右栏常驻预览与已选项。
- [ ] 助理卡片为「头部身份 + 描述 + 三格摘要 + 范围/底部操作」，名称是唯一详情入口。
- [ ] 助理未显式配置模型时，卡片不显示「默认模型」。
- [ ] MCP 服务卡片保持整行与内联展开，状态摘要用分隔点而不是一排胶囊。
- [ ] 折叠区标题显示数量或状态，按钮带 `aria-expanded`。
- [ ] 1280×900 下主任务与主操作首屏可见。
- [ ] 暗色与亮色主题都验证过对比度。
- [ ] `npx tsc -b --noEmit`、`npx eslint` 与相关页面测试通过。
