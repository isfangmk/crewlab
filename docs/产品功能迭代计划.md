# AI 工作台 — 后续产品功能迭代计划

> 文档版本：v1.0 · 2026-11-09  
> 基线：`docs/AI工作台-功能迭代.md`（P0 已基本落地）  
> 定位不变：以**对话为中心**的 Agent 工作台（Tool / Skill / MCP / 知识库 / 模型 / 审批）；运行时坚持 **Google ADK**，不做 AIOps、不做可视化工作流编排替代品。

---

## 0. 业界能力地图（调研摘要）

对照开源/自托管产品常见能力（主要来源：Open WebUI、Dify、LibreChat、Langfuse、mcp-workbench、Agent Studio、Copilot Studio / GitHub Copilot Harness 等公开文档与仓库说明），AI 工作台类产品通常覆盖以下能力族：

| 能力族 | 业界常见能力 | 代表产品倾向 |
| --- | --- | --- |
| **对话与模型** | 多厂商模型、流式输出、会话分叉/搜索、多模型对比、预设/Preset、附件与多模态 | LibreChat / Open WebUI |
| **智能体** | 人设与指令、工具白名单、知识绑定、子 Agent / 多 Agent 协作、Memory | Copilot Studio / Agenta / LibreChat Agents |
| **工具与扩展** | 内置 Tool、MCP、OpenAPI/插件、按需加载、人工审批策略 | mcp-workbench / Open WebUI / Agent Studio |
| **技能** | `SKILL.md` 渐进披露、市场/导入、斜杠命令、插件包 | mcp-workbench / Claude Code 生态 |
| **知识 / RAG** | 多格式入库、切块、向量 + 关键词混合检索、重排、引用溯源、检索 Playground | Dify / Open WebUI / mcp-workbench |
| **安全与治理** | 审批闸门、RBAC/SSO、审计日志、密钥托管、配额 | LibreChat / 企业向工作台 |
| **可观测与评测** | Trace、Token/成本、Prompt 版本、数据集与 Eval、Playground | Langfuse / Dify |
| **自动化与发布** | 定时任务、Webhook 触发、对外 API / Embed、IM 渠道 | Agenta / Dify / n8n |
| **执行沙箱** | 代码解释器、终端、浏览器、文件工作区 | Open WebUI / OpenHands / Agenta |
| **创作与体验** | Artifacts、语音、图像生成、笔记/频道 | LibreChat / Open WebUI |

**对本项目的取舍原则：**

1. **先做「对话 × Agent × Tool/Skill/MCP × 知识 × 审批」闭环的深度**，再扩展自动化与渠道。  
2. **不做**可视化 Chatflow/Workflow 画布（Dify/n8n 赛道）、不做设备/监控等 AIOps。  
3. 可观测、多用户、沙箱、发布渠道进入后续里程碑，且优先可插拔（对接 Langfuse 等）而非自研全家桶。

**技能包规范（对齐 `google.adk.skills`）**

- 目录结构：`SKILL.md`（YAML frontmatter + 正文）+ 可选 `references/`、`assets/`、`scripts/`；
  frontmatter 只允许 `name` / `description` / `license` / `compatibility` / `allowed-tools` / `metadata`。
- 平台侧属性写在 `metadata` 里随包往返：`risk`（safe / mutating / dangerous）、`category`、
  `adk_additional_tools`（技能声明的可调用工具）、`adk_inject_state`。
- ZIP 导入：允许整体套一层目录（自动剥前缀）；上限 2000 个条目、解压后 32MB；拒绝 zip slip 与非法相对路径；
  包内没有 `risk` / `category` 时导入弹窗必须显式选择。导出包可再次导入（round-trip 无损）。
- 落库：内置技能来自 `backend/skills/`（只读）；用户在平台创建 / 导入的技能存 `user_skills`，
  key 与内置重名时显式 400，不做静默覆盖。
- 可声明工具的两类来源：内置工具注册表（如 `query_knowledge`）与 MCP 探测缓存
  （wire 名 `mcp__<server>__<tool>`）。保存时按「内置 + MCP」全集校验，未知工具显式 400；
  MCP 工具的参数表由 `input_schema` 转换（`skill_params_from_schema`）。
- MCP 目录只读探测缓存、不在保存/列表时连远程：Server 停用或探测失败时声明仍合法，
  技能标 `inventory_only`（页面显示「不可用」），运行时该 Server 不会被挂载。
- MCP 工具默认走 MCP 工具集的 `search_tools` / `load_tool` 检索加载（不直接进初始上下文）；
  **技能声明的 MCP 工具例外**：装配时直接进入模型上下文（免检索），同 Server 的其余工具仍走检索。
  未挂载 / 未探测成功的 Server 不装配工具集，其工具既不可见也搜不到。
  技能正文仍要写明工具名与用途；声明本身的作用是把所属 Server 纳入可挂载集合。
- 助理装配：`user_agents.skills_json` 为 `NULL` = 继承全部技能，数组 = 只装配勾选的技能（`[]` = 全部不装）；
  技能声明的工具自动并入白名单且不允许被屏蔽（取消勾选技能才能去掉）。
  运行时 `agent_service.effective_allowed_tools` 还会再并一次：技能后加声明时，
  对应 MCP Server 仍会按 Server 整台挂载，不依赖保存助理时的那份快照。

## 3. 二、未开发功能的迭代

以下为当前产品**基本没有或仅占位**、但业界工作台普遍具备或强需求的能力。仍遵守：不自研 Agent 运行时；不做 AIOps；不做 Dify 式画布作为主路径。

### 3.1 P1 — 补齐「能用、可控、可查」

| ID | 功能 | 价值 | 备注 |
| --- | --- | --- | --- |
| N1 | **多用户与 RBAC** ✅ | 团队共用工作台；角色：管理员 / 开发者 / 只读 | 本地多用户已落地；SSO 见 N2 |
| N2 | **SSO / OIDC** | 对接企业 IdP | 可与 N1 同里程碑 |
| N3 | **运行可观测（对接优先）** | Trace、延迟、错误、token；优先接 Langfuse/OTel | 避免自研完整观测台 |
| N4 | **Prompt / 助理 Playground** ⏸ | 改人设与参数后侧栏试跑，不污染正式会话 | 暂缓：排在所有条目之后，本期不做 |
| N5 | **会话导出与分享** | Markdown/JSON 导出；只读分享链接（可选） | |
| N6 | **知识混合检索落地** | 见 K3；属「未做完的知识能力」 | 与已有知识库迭代重叠，单独立项便于排期 |

### 3.2 P2 — 自动化与协作

| ID | 功能 | 价值 | 备注 |

### 3.4 明确不纳入本产品主线（保持非目标）

- 可视化工作流画布、Zapier/n8n 式集成中台  
- 设备 / Edge / K8s / 监控告警 / WebSSH 等 AIOps  
- 自研 Agent Loop、自研审批执行器、绕过 ADK confirmation  
- 开放式公共 Skill 商店（可做「私有 Git 源」，不做运营型市场）

## 4. 建议路线图（季度视角）

```text
近程（1～2 个迭代）
  已有：C1–C3、A1–A3、T1–T2、S1–S2、M2/M5、K1–K4、G1–G2、E1–E3
  新建：N1（可先做本地多用户）、N3、N5、N6

  新建：N2、N7、N9、N10

  新建：N8、N11–N16（按业务信号裁剪）；C6 / N17 仅在有明确需求时启动
```

#### 审计覆盖面（G2 定稿口径）

审计表只回答「谁在什么时候改了什么、谁批准了什么」，不承担对话级追踪。

| 领域 | 已留痕动作 | 记录要点 |
| --- | --- | --- |
| 用户与权限 | `user.create` / `user.status` / `user.role` / `user.password_reset` / `user.delete` / `auth.login` | 邮箱、角色前后值；重置密码只记 id，不落明文；登录只记成功（失败尝试来自未认证请求，避免审计表被放大） |
| 审批 | `approval.approve` / `approval.reject` / `approval.batch_approve` / `approval.batch_reject` | 审批 id、理由、批量条数 |
| 工具调用 | `tool.run` / `mcp.tool_run` | 参数与结果各截断 500 字符，避免审计表被大输出撑爆 |
| MCP 配置 | `mcp.server_create` / `mcp.server_update` / `mcp.server_delete` | 名称、transport、endpoint、trusted、approval_policy、启用态 |
| 凭证 | `secret.create` / `secret.delete` / `secret.rotate` / `secret.verify` / `secret.export` | 名称、类型、轮换字段名、探测成败；不落新旧字段值，清单导出只含元数据 |
| 助理装配 | `agent.create` / `agent.update` / `agent.delete` | 模型、权限模式、max_turns、工具白名单；人设只记字符数 |
| 技能 | `skills.reload` | 重载条数与类别；技能目录变化会改变工具面 |
| 知识库 | `knowledge.doc_create` / `_update` / `_move` / `_delete` / `_upload` / `knowledge.reindex` | 文档 id、标题、路径；删除前先取标题，提交后仍可辨认 |
| 系统设置 | `setting.update` / `setting.reveal` / `setting.export` / `llm.save` | 键与值；揭示密钥只记厂商，永不落密钥；保存模型配置不落 api_key；快照导出只记行数与分类 |
| 会话对外 | `session.share` / `session.delete` / `session.batch_delete` / `session.model` / `session.agent` | 分享有效期、被删会话 id 与条数、切换到的 provider/model 与助理 id；不落消息正文 |
| 审计自身 | `audit.export` | 导出行数、是否脱敏、筛选条件；导出即敏感数据出库，必须留痕 |

明确不写审计：对话内单轮工具/技能调用（已由 `observation_turns` / `observation_tool_calls` 按 trace 记录，避免双写与噪声）、只读查询、会话标题/置顶等无追责价值的操作。**凭证明文与 LLM api_key 永远不进入审计表**；登录失败同样不落库（未认证请求的逐次写库会变成放大器）。

#### 脱敏导出规则（G3 定稿口径）

| 出口 | 脱敏范围 | 说明 |
| --- | --- | --- |
| 审计 CSV `GET /audit/export` | `detail` 递归脱敏（含历史脏数据） | 敏感键名整值替换为 `***`；字符串内嵌 `api_key=…` / `Bearer …` / `sk-…` 片段同样遮蔽；**脱敏没有关闭参数**，出库口径唯一 |
| 配置快照 `GET /system-settings/export` | `sensitive=true` 的项 | LLM `*_api_key` 恒为 `***`；其余设置原样导出，便于评审 |
| 凭证清单 `GET /secrets/export` | 全量 | 只导出名称/类型/说明/字段名/时间；密文与明文都不出库 |
| 凭证列表 `GET /secrets` | 全量 | 只回元数据；字段值只写不读 |

脱敏实现集中在 `backend/app/services/redaction.py`，复用日志脱敏的键名判定（`logging_setup.is_secret_key`），避免审计导出与日志各写一套名单。

### 4.4 本迭代落地记录（2026-11-10 · C3 引用来源 + A1 能力绑定可视化）

#### C3 引用与来源展示

原来的问题是「来源不可见」：`query_knowledge` / `web_search` 的结果只存在于工具卡的折叠 JSON 里，用户要么手动展开读 `items[].path`，要么只能相信模型正文里的引用序号。本轮把来源提成消息表面的一等元素。

| 子项 | 落地内容 | 关键实现 |
| --- | --- | --- |
| 分块定位 | `query_knowledge` 结果补 `chunk_index`，来源可以精确到「第 N 块」，不再只给文档级路径 | `knowledge_service.search_for_agent` 返回 `chunk.chunk_index` |
| 来源抽取 | 按工具契约解析：知识库读 `items[doc_id,title,path,chunk_index,excerpt,score]`，网页读 `results[title,url,snippet,summary,date,rerank_score]`；名称含 `search` / `knowledge` 的其它工具按 `items\|results` 通用形状兜底 | `web/src/components/SourcesBlock.tsx` `extractSources` |
| 去重合并 | 一次回答里多次检索，按 `kind + 链接 + 块序号` 合并去重（同一文档不同块保留为两条） | `mergeSources` / `collectToolSources` |
| 统一来源区 | 工具卡头部下方固定渲染 `来源 (N)`：`[序号]` + 标题链接（知识库 `/knowledge?doc=<id>`，网页 `https://` 新窗口）+ 路径 + `第 N 块` + 相关度三位小数 + 摘录（`line-clamp-3`）；不再藏在 `结果` JSON 里 | `SourcesSection`、`MessageBubble.tsx` `ToolCallSummaryBlock` |
| 气泡内收口 | 单条 assistant 消息含多个检索工具时，来源聚合到气泡底部一块，工具卡自身不再重复列；历史回放的工具卡各自成行，来源始终可见 | `AssistantBubble` 聚合 + `showSources={false}` |
| 正文锚点 | 工具说明要求模型用 `[序号]` 标注引用，使正文锚点与来源区序号对得上 | `adk_runtime/builtin_tools.py` `query_knowledge` 描述 |

配套测试：`backend/tests/test_builtin_tool_run.py::test_query_knowledge_returns_citation_locator`（工具出参含 `doc_id/title/path/chunk_index/excerpt/score`）、`web/src/components/SourcesBlock.test.tsx`（两种契约解析、去重、未知工具不误判）、`web/src/components/MessageBubble.test.tsx`（工具卡内展示、气泡聚合不重复）。

#### A1 能力绑定可视化

原来的助理编辑弹窗把「内置工具 / MCP 工具」摊平成上百个复选框，且与运行时口径不一致：勾 MCP 工具并不会按工具生效（挂载以 Server 为单位），勾了也会被对话开关或探测失败吞掉。本轮改为「先给真实结果，再让人勾」。

| 子项 | 落地内容 | 关键实现 |
| --- | --- | --- |
| 实际可见口径 | 顶部实时预览 `实际可见 N 个工具`：`MCP X` + `内置 Y` + `技能 Z` + `随开关 +W`，另显 `已屏蔽 K`；勾选/取消立刻变化 | `web/src/lib/capabilityPreview.ts` `previewCapabilities` |
| 分组呈现 | 按 `内置工具 / 技能 / MCP Server` 三组分列；内置工具标 `始终装配` / `随开关`，技能列出其注入的工具 | `web/src/components/CapabilityBinding.tsx` |
| 按 Server 挂载 | MCP 以 Server 为单位勾选（与 `agent_service.filter_mcp_servers_for_agent` 一致），Server 行展开看工具清单；未探测成功（`status !== 'ok'`）、已停用、无工具缓存的 Server 禁用并标注原因 | `previewCapabilities` 的 `mountedServers` / `unmountedServers` |
| 口径不一致提示 | 白名单不含任何 `mcp__*`（全部 Server 继承）、只勾了 Server 内部分工具（整台挂载，实际全部可见）、白名单残留目录里已不存在的工具，逐条给出说明；提供「恢复继承全部」清空白名单 | `partialServers` / `unknownWhitelist` / `whitelistHasMcp` |
| 屏蔽 | 内置工具、技能注入工具、MCP 工具均可「屏蔽」（写禁用名单，运行时 `before_tool_callback` 直接拒绝）；屏蔽与挂载是两件事，不复用同一个复选框 | `disallowedTools` 写入 + `blockedTools` 计数 |

配套测试：`web/src/lib/capabilityPreview.test.ts`（白名单为空/整台/部分/未知残留、探测失败 Server、屏蔽计数）、`web/src/pages/Agents.test.tsx`（Server 级勾选发出的白名单、可见数随勾选变化、屏蔽写入禁用名单）。

### 4.5 本迭代落地记录（2026-11-10 · A2 人设与示例 + A3 知识范围）

#### A2 人设与示例

原来的问题是「人设半边是死配置」：`critical_reminder` 存进库却从不进入运行时，少样本示例与输出格式约束根本没有字段。本轮把三段能力都做成真实生效的人设片段，并统一走一个组装函数。

人设片段顺序固定为：`system_prompt` → `## 必须遵守` → `## 输出格式` → `## 示例` → `## 知识范围`。

| 子项 | 落地内容 | 关键实现 |
| --- | --- | --- |
| 数据模型 | `user_agents` 新增 `output_format`（`free \| json \| checklist`，默认 `free`）、`examples_json`（`[{input, output}]`，最多 3 条）、`knowledge_scope_json` | `models_orm/agent.py` + `db_schema.py` `_REQUIRED_COLUMNS` 幂等补齐 |
| 人设组装 | `compose_persona(agent)` 一处组装，流式回合与审批恢复回合共用；`free` 不产生格式段，空提醒/空示例/空范围不产生空标题 | `agent_service.compose_persona` |
| 输出格式 | 服务端按枚举生成固定文案（`json` 只输出 JSON；`checklist` 按清单输出并标注证据/待验证），前端不自由填写，避免格式约束被写成另一段散文 | `_OUTPUT_FORMAT_INSTRUCTIONS` |
| 示例校验 | 非空字符串、`input`/`output` 都要有内容、≤3 条、单条 ≤2000 字符；超限/空串一律 400 并指出第几条，不做静默截断 | `agent_service.parse_examples` |
| 审计 | `_agent_audit_detail` 记录 `output_format`、示例条数、范围路径与文档 id 数；人设正文仍只记字符数 | `api/agents.py` |

#### A3 知识范围

原来的问题是「助理无权限制检索面」：`query_knowledge` 永远全库检索，助理只能靠提示词自我约束，范围外文档仍可能被召回。本轮把范围做成检索参数，在 SQL 层收口。

| 子项 | 落地内容 | 关键实现 |
| --- | --- | --- |
| 范围语义 | `paths` + `doc_ids` 取并集（OR）；路径匹配为 `path == p OR path.startswith(p + '/')`，避免勾 `网络` 误匹 `网络安全`；再与既有 `path`/`tags` 过滤 AND | `services/knowledge_scope.py` `scope_condition` |
| SQL 层收口 | 范围条件直接进 `search_docs` 的 where，不是检索后过滤；`search_for_agent` 透传 scope 并保留 `chunk_index` 引用定位 | `knowledge_service._apply_doc_filters` |
| 运行时绑定 | `build_knowledge_tools(scope)` 用闭包绑定 scope，内层函数仍名为 `query_knowledge`（`functools.wraps`），工具名与目录不变；`build_skill_toolset` → `agent_factory` → `stream_bridge` → `chat_service` / `approval_service` 全程下传 | `adk_runtime/builtin_tools.py`、`skills_service.py` |
| 保存校验 | 保存前 `validate_scope` 聚合 `unknown_paths / unknown_doc_ids` 一次报全，命中 0 篇直接 400，不做静默降级为「全库」 | `api/agents.py` |
| 编辑器预览 | `POST /knowledge/scope-preview` 返回 `doc_count` / 各路径命中数 / 不存在的路径与文档 id；编辑器实时显示「命中 N 篇」，未命中红字提示保存会被拒绝 | `api/knowledge.py`、`KnowledgeScopePicker.tsx` |
| 范围试检索 | `GET /knowledge/search` 新增 `scope_path` / `scope_doc` 重复参数，复用同一套 `scope_condition`，编辑器可先验证范围再保存 | 同上 |
| 前端编辑 | 模板从「只填正文」升级为「一次填正文 + 提醒 + 输出格式 + 示例」；`全部知识库 / 指定范围` 单选，目录含文档数多选、文档按标题搜索多选 | `PersonaFields.tsx`、`lib/personaTemplates.ts` |
| 详情可见 | 助理详情弹窗新增「关键提醒 / 知识范围 / 输出格式与示例」三块，配了不会看不见 | `Agents.tsx` |

配套测试：`backend/tests/test_agent_persona.py`（片段顺序与内容、`free` 无格式段、未知格式/示例超限/空串 400、创建更新 round-trip）、`backend/tests/test_knowledge_scope.py`（真实嵌入 + 真实 PG：路径范围、文档范围、并集、`scope=None` 不受影响、scope-preview 校验、带 scope 的检索不出范围外文档）、`web/src/lib/personaTemplates.test.ts`、`web/src/pages/Agents.test.tsx`（模板一键填四块、示例上下限、切换指定范围后 payload、预览命中数、未命中禁用保存、详情展示范围）。

浏览器实测：编辑 `ops-helper` → 套「SRE 排障」模板 → 选「指定范围」仅勾 `网络/DNS` → 试检索「DNS 解析失败」只出该目录命中 → 保存后开新会话问范围外问题（MySQL 慢查询），回答明确说明未检索到相关内容并按 `critical_reminder` / `output_format` 输出清单式结论与「待验证」标记，未出现范围外来源。
