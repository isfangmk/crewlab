## 0. 业界能力地图（调研摘要）

对照开源/自托管产品常见能力（主要来源：Open WebUI、Dify、LibreChat、Langfuse、mcp-workbench、Agent Studio、Copilot Studio / GitHub Copilot Harness 等公开文档与仓库说明），AI 工作台类产品通常覆盖以下能力族：

| 能力族 | 业界常见能力 | 代表产品倾向 |
| --- | --- | --- |
| **对话与模型** | 多厂商模型、流式输出、会话分叉/搜索、多模型对比、预设/Preset、附件与多模态 | LibreChat / Open WebUI |
| **智能体** | 人设与指令、工具白名单、知识绑定、子 Agent / 多 Agent 协作、Memory | Copilot Studio / Agenta / LibreChat Agents |
| **工具与扩展** | 内置 Tool、MCP、OpenAPI/插件、按需加载、人工审批策略 | mcp-workbench / Open WebUI / Agent Studio |
| **技能** | `SKILL.md` 渐进披露、市场/导入、斜杠命令、插件包 | mcp-workbench / Claude Code 生态 |
| **知识 / RAG** | 多格式入库、切块、向量 + 关键词混合检索、重排、引用溯源、检索 Playground | Dify / Open WebUI / mcp-workbench |
| **安全与治理** | 审批闸门、RBAC/SSO、审计日志、密钥托管、配额 | LibreChat / 企业向工作台 |
| **可观测与评测** | Trace、Token/成本、Prompt 版本、数据集与 Eval、Playground | Langfuse / Dify |
| **自动化与发布** | 定时任务、Webhook 触发、对外 API / Embed、IM 渠道 | Agenta / Dify / n8n |
| **执行沙箱** | 代码解释器、终端、浏览器、文件工作区 | Open WebUI / OpenHands / Agenta |
| **创作与体验** | Artifacts、语音、图像生成、笔记/频道 | LibreChat / Open WebUI |

**对本项目的取舍原则：**

1. **先做「对话 × Agent × Tool/Skill/MCP × 知识 × 审批」闭环的深度**，再扩展自动化与渠道。  
2. **不做**可视化 Chatflow/Workflow 画布（Dify/n8n 赛道）、不做设备/监控等 AIOps。  
3. 可观测、多用户、沙箱、发布渠道进入后续里程碑，且优先可插拔（对接 Langfuse 等）而非自研全家桶。

**技能包规范（对齐 `google.adk.skills`）**

- 目录结构：`SKILL.md`（YAML frontmatter + 正文）+ 可选 `references/`、`assets/`、`scripts/`；
  frontmatter 只允许 `name` / `description` / `license` / `compatibility` / `allowed-tools` / `metadata`。
- 平台侧属性写在 `metadata` 里随包往返：`risk`（safe / mutating / dangerous）、`category`、
  `adk_additional_tools`（技能声明的可调用工具）、`adk_inject_state`。
- ZIP 导入：允许整体套一层目录（自动剥前缀）；上限 2000 个条目、解压后 32MB；拒绝 zip slip 与非法相对路径；
  包内没有 `risk` / `category` 时导入弹窗必须显式选择。导出包可再次导入（round-trip 无损）。
- 落库：内置技能来自 `backend/skills/`（只读）；用户在平台创建 / 导入的技能存 `user_skills`，
  key 与内置重名时显式 400，不做静默覆盖。
- 可声明工具的两类来源：内置工具注册表（如 `query_knowledge`）与 MCP 探测缓存
  （wire 名 `mcp__<server>__<tool>`）。页面创建 / 编辑保存时按「内置 + MCP」全集校验，未知工具显式 400；
  ZIP 导入沿用磁盘技能口径，允许声明平台暂未实现的工具（编辑器列在「目录外」组，运行时不会挂载）；
  MCP 工具的参数表由 `input_schema` 转换（`skill_params_from_schema`）。
- MCP 目录只读探测缓存、不在保存/列表时连远程：Server 停用或探测失败时声明仍合法，
  技能标 `inventory_only`（页面显示「不可用」），运行时该 Server 不会被挂载。
- MCP 工具一律走 MCP 工具集的 `search_tools` / `load_tool` 检索加载，不直接进初始上下文；
  技能声明的 MCP 工具同样只进检索目录（不做免检索直塞），声明的作用是把所属 Server
  纳入可挂载集合，并保证工具在白名单里不被漏掉。
  **白名单（`user_agents.tools_json`）非空时是唯一口径**：Server 内没勾选的工具既不进检索目录，
  也不可直接调用（`build_searchable_mcp_toolsets(allowed_tools=...)` 逐工具收口）。
  白名单为空 = 继承全部，此时整台 Server 的工具都可检索。
  未挂载 / 未探测成功 / 白名单里一个工具都没勾到的 Server 不装配工具集，其工具既不可见也搜不到。
  技能正文仍要写明工具名与用途；声明本身的作用是把所属 Server 纳入可挂载集合。
- 助理装配：`user_agents.skills_json` 为 `NULL` = 继承全部技能，数组 = 只装配勾选的技能（`[]` = 全部不装）；
  技能声明的工具自动并入白名单且不允许被屏蔽（取消勾选技能才能去掉）。
  运行时 `agent_service.effective_allowed_tools` 还会再并一次：技能后加声明时，
  对应 MCP Server 仍会被纳入挂载集合，不依赖保存助理时的那份快照。

配套测试：`backend/tests/test_knowledge_docs_list.py`（标题 `q` 命中与不命中、`path_prefix` 命中本级与子级、分页 `total` 不随当页条数变化、`sort_dir` 改变顺序、非法排序 400、`builtin` 两组互斥、目录树按组聚合）、`web/src/pages/Knowledge.test.tsx`（标题筛选走服务端 `q`、来源筛选走服务端 `source_type`、排序走服务端 `sort_dir`、语义检索与标题筛选两个输入框互不干扰）。浏览器实测：标题筛选「DNS」把 162 篇收窄到 1 篇；语义检索「雷达校准」返回 10 条命中并展示 RRF / 向量相似度 / 关键词排名，两条链路互不影响。
