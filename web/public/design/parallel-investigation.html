1交互：侧栏是工作台，对话只留结论

  • 右栏常驻排查工作台：worker 状态/日志/发现/预算都在侧栏，主对话不刷过程行
  • 主对话只出一个折叠块「并行排查 · N 路」，摘要带计数与失败数，可展开看每路一句话结论
  • 运行中的路默认展开、活动行逐条渐入；失败的路露出错误预览 + 重试/跳过
  • 汇总回答带 [1] [2] 引用角标，点开即定位到侧栏对应发现（证据可溯）

2安全与预算：worker 全部只读

  • worker 默认只读工具，禁写操作与审批放行；危险动作只能出现在主代理层
  • 每路独立预算（token/时长/步数）+ 全局上限，超时即失败可重试，预算用量实时可见
  • 发现必须带证据（工具调用 id / 原始字段引用），支持后续数字交叉校验
  • worker 结论只回结构化 findings，不回原始数据，省 token 也防上下文串扰

3技术口径：保持 ADK，不自研编排

  • 主代理持 dispatch_investigation 工具：内部并行起子代理实例（复用现有子助理装配）
  • 已知排查套路走工作流 DAG 更省；开放式问题才自由扇出，两者可互相调用
  • 数据面：一次排查 = 一张 dispatch 记录 + N 条 worker 运行行，挂观测 trace，复用现有可观测链路
  • 对话时间线（C5 回退项）日后若重启，可挂在这套 worker 数据上做可选侧栏视图
