# 部署与运维指南

适用版本：当前主干（FastAPI + React/Vite + Redis 强依赖，单机或多 worker）。架构全景见《整体架构》。

## 服务构成

| 服务 | 技术栈 | 默认地址 | 说明 |
|---|---|---|---|
| Redis | Redis（用户自备 Windows 版） | 127.0.0.1:6379 | **强依赖**：帧/事件/通知 Stream、锁、停止信号、共享状态；不可用则后端启动失败 |
| 后端 API | FastAPI + Uvicorn | http://127.0.0.1:18080 | REST + SSE，日志写 `logs/backend.log` |
| 前端 | Vite 开发服务器 | http://127.0.0.1:5173 | 生产构建另行打包，日志写 `logs/frontend.log` |
| 可观测 MCP | mcp-obs（SSE） | http://127.0.0.1:18099 | obs-tools，日志写 `logs/mcp.log` |
| 沙盒 | 本地进程或 Docker | - | 由 `SANDBOX_EXECUTOR` 决定（local / docker），默认 docker |

> 启动顺序：`all` 按 `redis → backend → frontend → mcp`。Redis 必须先起，否则后端因强依赖启动失败、前端随之不可用。

## 启停脚本（仓库 `scripts/` 目录）

- `service.ps1 start|stop|restart [backend|frontend|mcp|redis|all]`：统一启停，默认 `all`；PID 记录在 `logs/<name>.pid`，重启先停旧再起新并输出 PID 与日志路径。
- `backend-typecheck.ps1`：类型检查。
- `eval-gate.ps1`：评测门禁。

**纪律：**

- 后端禁用 `--reload`。改动后端代码后必须执行 `scripts/service.ps1 restart backend` 使生效，并访问 `/healthz` 确认 `{"status":"ok"}`。
- 改完后端用 `scripts/service.ps1 restart backend`，不要用 `--reload`。
- Redis 路径写在 `service.ps1` 的 redis 分支（`redis-server.exe` + `redis.windows.conf`），用户自备并按需修改。

## 多 worker

```powershell
# Linux / 类 Unix：设 UVICORN_WORKERS=N 即启用多 worker（redis 强依赖已保证跨进程正确性）
$env:UVICORN_WORKERS = "4"; scripts/service.ps1 restart backend
```

- `service.ps1` 仅在设置了 `UVICORN_WORKERS` 时才给 uvicorn 加 `--workers`；本地默认单 worker。
- **Windows 限制**：uvicorn `--workers` 用 SO_REUSEPORT 共享监听 socket，Windows 上报 `OSError WinError 10022`，只有 1 个 worker 存活。故本地默认单 worker；多 worker 部署放 Linux。
- 多 worker 正确性依赖 Redis：帧/事件 Stream、分布式锁、停止信号广播、常驻循环 Leader 选举、通知总线——见《Redis强依赖与多worker协同架构》。

## 数据存储

- `data/ai_workbench.db`：SQLite 业务库（生产可切 PG），会话、消息、产出物、审批、审计、配置等全部表。
- `data/vectors.db`：独立向量库，单表 `vector_items`，按 namespace 区分语料（knowledge_chunks / memory_items / mcp_tools）；生产可切 pgvector；`VECTOR_BACKEND=none` 时向量依赖功能显式失败。
- 知识库上传原件落盘保存，可在文档详情页下载。
- 备份：停服后整体拷贝 `data/` 目录即可；两库分开便于单独迁移。**Redis 只存协同态，不需持久备份**（权威数据在 DB）。

## 关键环境变量（`backend/.env`）

| 变量 | 用途 |
|---|---|
| `DATABASE_URL` | 业务库连接串（sqlite+aiosqlite 或 postgresql+asyncpg） |
| `REDIS_URL` | **必填**：Redis 连接串；缺失/连不上则后端启动失败（强依赖） |
| `VECTOR_BACKEND` | 向量后端（sqlite / pgvector / none） |
| `EMBEDDING_BASE_URL` / `EMBEDDING_MODEL` / `EMBEDDING_API_KEY` / `EMBEDDING_DIM` | 文本嵌入服务（内网 key 可留空） |
| `SEED_LLM_PROVIDER` / `SEED_LLM_MODEL` / `SEED_LLM_API_KEY` 等 | 首个 LLM 供应商种子配置 |
| `LITELLM_LOCAL_MODEL_COST_MAP` | 置 True 让 LiteLLM 用本地价格表；否则首次计价拉 GitHub 超时会让首个回合白等 10+ 秒 |
| `AUTH_ADMIN_EMAIL` / `AUTH_TOKEN` | 初始管理员账号（保密） |
| `CREDENTIAL_ENCRYPTION_KEY` | 第三方凭证加密密钥（保密，独立于 AUTH_TOKEN） |
| `SANDBOX_EXECUTOR` / `SANDBOX_IMAGE` / `SANDBOX_TIMEOUT_SECONDS` / `SANDBOX_NETWORK_ENABLED` | 沙盒执行器与安全边界 |
| `UVICORN_WORKERS` | 仅在设值时启用多 worker（Windows 本地勿设） |

## 健康检查

- `GET /healthz` 返回 `{"status":"ok"}` 即服务正常（Redis 强依赖已就绪）。
- `redis-cli ping` 返回 `PONG` 确认 Redis 可用。
- 观测页（/observability）提供运行期指标与工具调用观测。

## 常见故障提示

- **前端打不开、后端起不来**：先看 `logs/backend.log` 与 Redis 是否 `PONG`——Redis 停则后端强依赖启动失败，前端随之全断。
- **服务调用结束后退出**：若用工具脚本 `Start-Process` 启动，注意 Windows Job Object 会在工具 shell 结束时连带杀掉后代进程；用 `service.ps1` 启停可规避。
- 其余排障见 `knowledge_base/diagnostics/`（常见故障、磁盘、DNS、systemd、TLS）。
