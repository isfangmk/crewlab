# 系统设置与系统时区架构

系统设置是通用键值配置（`agent / observability / knowledge / usage` 四类），其中**系统时区**是被用量切日界、人设时间等多处引用的关键配置。敏感值不进通用设置——API key 走 provider 配置的 reveal 通道（见《LLM供应商与模型配置架构》）。

## 通用键值设置（app_settings_service.py / api/system_settings.py）

- **存储**：`AppSetting(key=="{category}.{key}", value)`；支持类目 `agent / observability / knowledge / usage`。
- **校验**：`put_setting()` 按类目白名单 + 值校验（chunk_size≥64、overlap≥0、rrf_min_score 有限非负、daily_token_soft_limit 空=不限否则≥1、llm_timeout 30..900、output_locale ∈ {"",zh,en} 等）；`sensitive=true` 直接拒绝（通用设置不允许敏感值）。
- **reveal 脱敏**：通用设置导出对 sensitive 项输出 `MASK`；真正需要明文时走 `llm_admin.reveal_api_key(db, provider_id)`（见《LLM供应商与模型配置架构》）并写审计 `setting.reveal`。

部分常用键与消费方：

| 键 | 用途 | 消费方 |
|---|---|---|
| knowledge.chunk_size / chunk_overlap | 知识切块窗口 | 《知识库与检索架构》 |
| knowledge.rrf_min_score | 混合检索阈值 | 《知识库与检索架构》 |
| knowledge.approval_timeout_hours | 审批超时/SLA 80% | 《工具执行权限与审批规则》 |
| usage.daily_token_soft_limit | 用量软限额（只提醒） | 《沙盒与可观测架构》 |
| observability.timezone | 系统时区（见下） | 用量切日界 / 人设时间 |
| default_provider | 默认 LLM provider | 《LLM供应商与模型配置架构》 |

## 系统时区

键 `observability.timezone`，`SYSTEM_TIMEZONES` 是固定偏移表（UTC / UTC+00:00 / UTC+05:30 / UTC+08:00 / UTC+09:00 / UTC-05:00 / UTC-08:00，共 7 项；UTC 与 UTC+00:00 同义），默认 `UTC+08:00`。

- **固定偏移而非 IANA 时区库**：避免依赖系统 tzdata，跨环境行为一致。
- `get_system_timezone()` 返回 (配置名, tzinfo)，缺配置/非法显式失败（不静默用本地时区）。
- 被 `usage_service._day_expr()` 用于切日界（用量按日的口径见《沙盒与可观测架构》）；人设的「当前时间」按本地时间 + 时区标签 + 星期每回合现算（见《Agent装配与子代理架构》）。
- OS 层 NTP/时区排查见知识库 `时区/NTP 与时区.md`。

## 设计原则

1. **配置与敏感值分离**：通用设置拒绝 sensitive，API key 走 provider reveal 通道。
2. **缺配置显式失败**：时区缺失/非法直接报错，不静默兜底。
3. **值校验前移**：类目白名单 + 逐键校验在写入时完成，避免脏配置扩散到各消费方。
