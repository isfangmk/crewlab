# 数据模型与权限说明

## 角色

用户表 `users` 的 role 三档：**admin**（全权）/ **developer**（开发与写操作）/ **viewer**（只读，写接口 403）。登录态在 `api_tokens`，与用户一对多。工具执行层面的风险标签、MCP 审批策略与审批规则见《工具执行权限与审批规则》。全库表清单与字段见《数据模型全景》。

## 鉴权与凭据机制（auth_service.py / api/deps.py）

- **单管理员 bootstrap**：`ensure_bootstrap_admin()`（main.py lifespan 调用）在库无用户时用 `AUTH_ADMIN_EMAIL` + `AUTH_TOKEN`（作为 password）建首个 admin；**已有用户却缺 bootstrap 管理员时拒绝静默创建**。bootstrap 管理员不可禁用/降角色/删除。登录 `authenticate()` 校验后签 30 天 token。
- **单向哈希存储**：密码用 `pbkdf2_sha256$salt$digest`（salt=token_hex(16)）并 `hmac.compare_digest` 校验；API token 用 `hash_token()` = SHA256 hex 单向存储（`api_tokens.token_hash` 唯一），明文只在 login 返回一次。同款 `hash_token` 被 `share_tokens`、`eval_share_tokens`、`trigger_rules.webhook_token_hash` 复用（见《数据模型全景》）。`resolve_bearer()` 校验过期与用户 active 状态。
- **鉴权依赖**：`require_auth`（Bearer + `set_user_id`）、`require_admin`、`require_not_viewer`（viewer 写操作 403）。
- **request_id 贯穿**：`middleware_request_id.py` 从 `x-request-id` 或 uuid4 注入并写响应头；`request_context.py` 用 3 个 ContextVar（request_id/user_id/session_id）；`logging_setup.ContextFilter` 把它们注入日志。
- **日志脱敏**：`logging_setup.py` 的 `is_secret_key()`（整名匹配 + vendor 后缀）+ `redact_secrets()`（Bearer / sk- / AUTH_TOKEN 正则 + key=value 替换），`RedactingFormatter` 格式化时统一脱敏；审计导出/配置快照复用同判定。第三方凭证加密密钥是独立的 `CREDENTIAL_ENCRYPTION_KEY`，与 AUTH_TOKEN 解耦（见《凭证与只读分享架构》）。

## 表的两大类

**配置类（备份必留，日常不动）**

| 表 | 内容 |
|---|---|
| app_settings | 系统设置（如系统时区 observability.timezone） |
| llm_providers / secret_credentials | LLM 供应商与加密凭据 |
| mcp_servers / mcp_oauth_* / mcp_tool_embeddings | MCP 服务器配置与工具语义索引 |
| user_agents | 助理（Agent）配置 |
| workflows / trigger_rules | 工作流定义、触发器规则 |
| approval_rules | 审批规则（工具名通配×助理×风险 → 自动放行/需审批/禁用/升级） |
| knowledge_sources / published_channels / user_skills | 知识外部源、发布渠道、技能开关 |
| users / api_tokens | 账号与登录态 |

**数据类（可清空重建）**

| 表 | 内容 |
|---|---|
| chat_sessions / chat_messages / chat_attachments / artifacts | 会话、消息、附件、产出物 |
| approvals | 审批（含 ask_user 的用户答案） |
| audit_logs | 审计日志 |
| sandbox_executions | 沙盒执行记录 |
| memory_items / knowledge_docs / knowledge_chunks | 记忆、知识文档与分块 |
| eval_datasets / eval_cases / eval_runs / eval_* | 评测资产与结果 |
| workflow_runs / workflow_node_runs / trigger_runs | 运行记录 |
| observation_turns / observation_tool_calls / events | 观测数据 |
| share_tokens / eval_share_tokens | 分享令牌 |
| sessions / user_states / app_states | ADK 运行态（`adk_internal_metadata` 存 schema 版本，勿删） |

## 向量库

`data/vectors.db` 单表 `vector_items`，namespace 对应来源表：knowledge_chunks（知识库）、memory_items（记忆）、mcp_tools（MCP 工具索引）。清数据时按 namespace 同步清理，mcp_tools 属配置衍生物应保留。

## 审计

- 写操作全覆盖：会话增删改、记忆 CRUD、沙盒运行、工作流停跑/节点试跑、评测门禁、助理试跑、LLM 测试等。
- **消息发送不进审计**（核心高频操作，消息已全量落 chat_messages）。
- 动作/资源存英文原始值，中文在前端展示层映射；历史行不迁移。

## 知识库入库链路

上传（.md/.txt/.pdf/.docx）→ 提取文本 → 分块 → 向量化 → knowledge_docs + knowledge_chunks + vector_items（namespace=knowledge_chunks）。原件另存可下载。检索命中会记录文档热度用于排序。
