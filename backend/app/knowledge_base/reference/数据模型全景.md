# 数据模型全景

本篇是**全库业务表的按域速查全景**：只做「表清单 + 关键字段/关系/约束」，按 10 个域分组，供同步进向量库后做 RAG 检索时一眼定位「哪张表管什么、字段怎么约束」。**不重复机制讲解**——某域的流转机制、回调挂接、失败兜底等详见对应 `concepts/` 文档，鉴权三角色与 token 口径详见《数据模型与权限说明》（两篇互补，角色口径不在本篇展开）。

范围：`backend/app/models/` 下 43 张 ORM 表 + 独立向量库单表 `vector_items` + ADK 自管运行态表（见文末专节）。所有表主键/外键/级联/唯一/状态枚举均按源码核对，状态枚举写的是代码中出现的取值（业务可能扩展，以源码为准）。

## 一、用户鉴权

| 表名 | 用途 | 关键字段或约束 |
|---|---|---|
| users | 工作台本地账号 | `id` 自增主键；`email` 唯一非空；`password_hash`（PBKDF2-HMAC-SHA256，非明文）；`role` ∈ admin/developer/viewer；`status` ∈ active/disabled（默认 active）；`created_at`/`updated_at` |
| api_tokens | 登录签发的 Bearer Token | `id` 自增主键；`user_id` → `users.id` **ON DELETE CASCADE**、有索引；`token_hash` String(128) 唯一非空（= `hash_token(明文)`，明文只返回一次，见「token_hash 复用面」）；`expires_at` 可空（NULL=不过期） |

> 三角色权限口径、登录态生命周期见《数据模型与权限说明》；工具执行层风险标签与审批策略见《工具执行权限与审批规则》。

## 二、助理与技能

| 表名 | 用途 | 关键字段或约束 |
|---|---|---|
| user_agents | 用户自定义助理配置（内置 default 不落库） | `name` String(128) 主键（助理唯一标识）；`display_name`；`system_prompt`/`critical_reminder`/`when_to_use`；`allowed_tools_json`/`disallowed_tools_json`；`permission_mode`；`model`/`max_turns`；`output_format` ∈ free/json/checklist（默认 free）；`examples_json`（≤3 条）；`knowledge_scope_json`（空=继承全部知识库）；`skills_json`（NULL=继承全部技能，`'[]'`=不装配）；`sub_agents_json`（NULL=无委托）；`created_at`/`updated_at` |
| user_agent_versions | 助理配置版本快照（更新即落一版，回滚读快照再生成一版） | `id` 自增主键；`agent_name` → `user_agents.name` **CASCADE**、有索引；`UniqueConstraint(agent_name, version)`，`version` 单助理内单调递增（1=创建快照）；`snapshot_json`（整份配置序列化）；`change_summary`；`created_by`；`restored_from_version`（回滚来源，正常保存为 NULL） |
| user_skills | 用户自建/导入技能（SKILL.md 全套资源存库；内置磁盘技能不落库） | `key` String(64) 主键；`description`；`preapproved_tools`（ADK 实验字段，不据此放行审批）；`risk` ∈ safe/mutating/dangerous（平台新增，非 ADK 规范）；`skill_group`（`group` 是 PG 保留字故改名）；`origin` ∈ created/imported（builtin 由目录推断）；`instructions`（L2 正文）；`metadata_json`；`references_json`/`assets_json`/`scripts_json`（资源路径→内容，assets 二进制走 base64）；`created_at`/`updated_at` |

> 装配、版本回滚、子代理委托机制见《Agent装配与子代理架构》；技能加载与资源分层见《Skill架构》。

## 三、会话消息

| 表名 | 用途 | 关键字段或约束 |
|---|---|---|
| chat_sessions | 工作台对话会话元数据 | `id` String(36) 主键；`title`/`provider`/`model`；`agent_id` 可空；`page_context_json`（全局助理页面快照，无则 NULL）；**`adk_user_id` String(64) 非空**（业务会话与 ADK 运行态的桥）；`thinking_enabled`/`web_search_enabled`（每会话独立记忆）；`pinned`/`archived`；`owner_user_id` 可空有索引；`created_at`/`updated_at` |
| chat_messages | 投影到前端的消息（正文/工具意图/工具卡/思考） | `id` String(128) 主键（含流式合成 id，如 `tool-card-<id>`）；`session_id` → `chat_sessions.id` **CASCADE**；`role`；`kind` ∈ user/assistant/tool_intent/tool_card/thinking/system（默认 message）；`content`；`tool_call_json`；`attachments_json`（附件 id 列表）；`stats_json`（仅最后一条 assistant 写，缺失为 NULL 不造假 0）；`seq`；`interrupted`（插话打断写入标记，默认 0；表结构变更由 `scripts/add_chat_message_interrupted.py` 补列） |
| chat_attachments | 消息引用的附件（内容 base64 存库） | `id` String(36) 主键；`session_id` → `chat_sessions.id` **CASCADE**、有索引；`name`/`mime_type`/`size`；`data_url`。mime 放行图片（png/jpeg/webp，5MB）与技能 zip（`application/zip`/`x-zip-compressed`，32MB，`max_bytes_for_mime` 分流） |
| artifacts | 工具执行的结构化产出物（图表/表格/文件/文本） | `id` String(36) 主键；`session_id` → `chat_sessions.id` **CASCADE** 可空有索引；`tool_call_id`、`message_id`（截断/重发时精删）均有索引；`seq`；`kind` ∈ chart/table/file/text；`payload_json`（结构化内容）；`data_bytes`（file 原始字节）；`file_name` |

> 会话与消息机制、产出物通道见《对话与智能体架构》《产出物与图表架构》。

## 四、知识向量

| 表名 | 用途 | 关键字段或约束 |
|---|---|---|
| knowledge_docs | 知识文档正文与元数据 | `id` String(36) 主键；`source_type`；`title`/`title_en`/`content`/`path`/`url`；`tags`（PG 用 JSONB、SQLite 用 JSON 文本）；`enabled`（停用不检索、切块保留可恢复）；`source_filename`/`source_mime`/`source_bytes`（上传原件信息）；`hit_count`/`last_hit_at`（检索热度，同文档一次检索只计 1 次）；`external_source_id` → `knowledge_sources.id` **CASCADE** 可空有索引；`external_key`/`external_hash`（外部源增量同步）；`created_at`/`updated_at` |
| knowledge_chunks | 文档切块正文（**向量不在此表**） | `id` 自增主键；`doc_id` → `knowledge_docs.id` **CASCADE**、有索引；`chunk_index`；`content`；`created_at`。向量按切块 id 写入独立 `vector_items`（namespace=`knowledge_chunks`，ref_id=`str(chunk.id)`） |
| knowledge_sources | 外部知识源（URL 页面/Git 仓库）接入配置与同步状态 | `id` String(36) 主键；`name` 唯一非空；`kind` ∈ url/git；`location`；`branch`/`path_prefix`/`knowledge_path`；`enabled`；`sync_status` ∈ idle/syncing/ok/error；`last_error`/`last_synced_at`/`last_duration_ms`；`etag`/`last_modified`（条件请求 304 跳过下载）；`created_by`；`created_at`/`updated_at` |
| memory_items | 跨会话长期记忆（语义条目，向量独立） | `id` String(36) 主键；`content`；`scope_agent_id` 可空有索引（NULL=全局记忆，所有助理可回忆）；`source_session_id`；`enabled`；`created_by`；`created_at`。向量写入 `vector_items`（namespace=`memory_items`）；`VECTOR_BACKEND=none` 时功能不可用 |

> 入库链路（上传→抽取→分块→向量化）、检索命中与热度、向量库分域见《知识库与检索架构》；向量表本体见文末「ADK 与向量库边界」及《数据模型与权限说明》。

## 六、工作流任务图

|---|---|---|
| workflows | 工作流画布定义与版本 | `id` 自增主键；`name` 唯一非空；`description`；`definition_json`（draft 定义）；`published_definition_json`（发布快照，草稿改动不影响）；`status` ∈ draft/published；`version`（仅发布 +1）；`published_at`（NULL=从未发布）；`validation_error`；`created_at`/`updated_at` |
| workflow_runs | 一次工作流执行 | `id` 自增主键；`workflow_id` → `workflows.id` **CASCADE**、有索引；`run_uid` 唯一有索引（对外展示/日志对照）；`definition_json`（运行时定义快照）；`workflow_version`；`workflow_status` ∈ draft/published（本次选用的定义来源）；`status` ∈ running/succeeded/failed/waiting/stopped；`trigger`/`triggered_by`；`input_json`/`output_json`/`error`/`duration_ms`；`finished_at` |
| workflow_node_runs | 单次 ADK 静态图节点执行 | `id` 自增主键；`run_id` → `workflow_runs.id` **CASCADE**、有索引；`node_id`；`node_kind` ∈ agent/function/join/start；`attempt`（循环节点 >1）；`status` ∈ succeeded/failed；`input_json`/`output_json`/`error`/`duration_ms`；`route`（分支/循环选中路由）；`created_at` |
| task_graph_runs | 一次统一任务图运行（取代旧 plan/investigation 四表） | `id` 自增主键；`graph_uid` 唯一有索引（工具结果/事件/API 通用标识）；`session_id` → `chat_sessions.id` **CASCADE**、有索引；`card_message_id`；`title`/`question`；`status` ∈ draft/running/paused/succeeded/failed/stopped；`spec_json`/`config_json`/`findings_json`（发现编号不复用）；`error`/`duration_ms`；`created_by`；`created_at`/`started_at`/`finished_at` |
| task_graph_nodes | 任务图单节点（执行前可编辑，执行后落结论/轨迹/用量） | `id` 自增主键；`graph_id` → `task_graph_runs.id` **CASCADE**、有索引；`node_uid` 唯一有索引（事件路由）；`local_id`（图内 id，如 A/B/C）；`depends_on_json`/`order_index`（拓扑渲染）；`name`/`target`/`instruction`；`tools_json`（非空则收窄工具面）；`status` ∈ pending/running/succeeded/failed/skipped/stopped；`attempt`；`summary`/`findings_json`/`tool_trace_json`/`log_text`/`usage_json`/`error`/`duration_ms`；`started_at`/`finished_at` |
| trigger_rules | 自动化触发器（Cron/Webhook，驱动工作流或助理会话） | `id` 自增主键；`name`；`kind` ∈ cron/webhook；`cron_expr`（cron 型五段表达式）；`target_kind` ∈ workflow/agent；`workflow_id` → `workflows.id` **CASCADE** 可空；`agent_id`/`prompt`/`values_json`；`enabled`；`max_retries`；`webhook_token_hash` 唯一（webhook 型 = `hash_token(明文)`，其他类型存唯一占位值）；`next_fire_at`/`last_fired_at`；`created_by` |
| trigger_runs | 一次触发的执行留痕 | `id` 自增主键；`trigger_id` → `trigger_rules.id` **CASCADE**、有索引；`status` ∈ running/waiting/succeeded/failed；`attempt`；`error`；`ref_id`（= 工作流 `run_uid` 或会话 id）；`started_at`/`finished_at` |

> 工作流发布/草稿、DAG 展开、任务图多代理排查与触发器调度机制见《工作流与任务图架构》；多 worker 协同见《Redis强依赖与多worker协同架构》。

## 七、评测

|---|---|---|

| eval_judge_configs | LLM 评分配置（与评测集 1:1） | `id` 自增主键；`dataset_id` → `eval_datasets.id` **CASCADE**、**unique**、有索引；`enabled`；`rubric`（评分标准）；`judge_provider`/`judge_model`（空=跟随目标模型）；`pass_score`（0–5，默认 3.0）；`created_at`/`updated_at` |
| eval_judge_scores | 一次 LLM 评分（按维度打分留理由） | `id` String(32) 主键；`result_id` → `eval_case_results.id` **CASCADE**、有索引；`dimension`；`score`（0–5）；`reason`；`judge_model`（解析失败记 parse_error）；`created_at` |
| eval_annotations | 人工标注（对单条结果给判定与备注） | `id` String(32) 主键；`result_id` → `eval_case_results.id` **CASCADE**、有索引；`annotator_user_id`；`label` ∈ good/needs_work/bad；`comment`；`created_at` |
| eval_share_tokens | 评测运行只读分享令牌（与会话分享分表，避免动既有表） | `id` 自增主键；`run_uid` → `eval_runs.run_uid` **CASCADE**、有索引；`token_hash` String(128) 唯一（= `hash_token(明文)`，明文只返回一次）；`created_by`；`expires_at` 必填；`created_at` |

> 用例断言、门禁判定、LLM 判分、红队种子、人工标注与分享机制见《评测系统架构》。

| mcp_tool_embeddings | MCP 工具检索元数据（**向量本体在 vector_items**） | `id` 自增主键；`server_id` → `mcp_servers.id` **CASCADE**、有索引；`tool_name`；`search_text`；`content_hash`（向量复用与一致性校验）；`UniqueConstraint(server_id, tool_name)`；`updated_at`。向量 namespace=`mcp_tools`，ref_id=工具 wire 名 |
| mcp_oauth_tokens | MCP OAuth 授权令牌（服务级共享，admin 授权一次全工作台生效） | `id` 自增主键；`server_id` → `mcp_servers.id` **CASCADE**、**unique**；`payload_ciphertext`（access/refresh token 等整体 **Fernet 密文**）；`created_at`/`updated_at` |
| mcp_oauth_states | OAuth 授权在途 state（一次性 CSRF 防护，回调后即删） | `id` 自增主键；`state` 唯一非空；`server_id` → `mcp_servers.id` **CASCADE**、有索引；`code_verifier`；`expires_at` 必填；`created_at` |

> 供应商/凭证/MCP 全链路机制见《LLM供应商与模型配置架构》《凭证与只读分享架构》《MCP全链路架构》。

## 备份语义：配置类表 vs 数据类表

- **配置类（备份必留，日常不动）**：`app_settings`、`llm_providers`、`secret_credentials`、`mcp_servers`/`mcp_oauth_*`/`mcp_tool_embeddings`、`user_agents`/`user_agent_versions`、`workflows`/`trigger_rules`、`approval_rules`、`knowledge_sources`、`published_channels`、`user_skills`、`users`/`api_tokens`。丢表等于丢系统能力，恢复成本高。
- **数据类（可清空重建）**：`chat_sessions`/`chat_messages`/`chat_attachments`/`artifacts`、`approvals`、`audit_logs`、`sandbox_executions`、`memory_items`/`knowledge_docs`/`knowledge_chunks`、全部 `eval_*`、`workflow_runs`/`workflow_node_runs`/`trigger_runs`、全部 `observation_*`、`share_tokens`/`eval_share_tokens`、ADK 运行态表。
- **备份方式**：两类都在同一份业务库（SQLite 文件在 `data/`），**停服后整体拷贝 `data/` 即可**——配置类务必保留，数据类按需清理时可按 namespace 逐域删。
- **向量库独立**：`data/vectors.db` 单表 `vector_items` 不在 `data/` 业务库拷贝范围内，需单独备份/清理；清数据时按 namespace 同步处理，`mcp_tools` 属配置衍生物应保留（详见《数据模型与权限说明》）。

## token_hash 复用面

`auth_service.hash_token()` = `hashlib.sha256(raw.encode()).hexdigest()`——**SHA256 hex、单向、不可反解**，库内只存摘要，**明文仅在签发响应里返回一次**，丢失只能重新签发：

| 载体 | 字段 | 备注 |
|---|---|---|
| api_tokens | `token_hash`（唯一） | 登录 Bearer Token |
| share_tokens | `token_hash`（唯一） | 会话只读分享 |
| eval_share_tokens | `token_hash`（唯一） | 评测运行只读分享（与会话分享分表） |
| trigger_rules | `webhook_token_hash`（唯一） | webhook 型触发器校验；非 webhook 型存唯一占位值 |

同口径的还有 `published_channels.key_hash`（同样由 `hash_token()` 生成，只是列名不同）。注意与「加密可解密」区分：`secret_credentials.fields_ciphertext`、`mcp_oauth_tokens.payload_ciphertext` 是 **Fernet 密文**（可逆，依赖密钥），`llm_providers.api_key`、`users.password_hash` 另有各自存储口径——不要把它们与单向 token hash 混为一谈。

## ADK 与向量库边界（不在 models/ 的表）

- **ADK 自管运行态**：`sessions`、`events`、`user_states`、`app_states` 由 `google.adk.sessions.DatabaseSessionService` 管理（`app/adk_runtime/session_store.py` 复用业务库 engine 建表），**不在 `backend/app/models/` 目录**，无对应 ORM 文件，不要用业务迁移工具管理它们。业务会话通过 `chat_sessions.adk_user_id` 与 ADK session 关联。
- **`adk_internal_metadata`**：ADK `prepare_tables()` 写入的 schema 版本表，**勿删**（删后 ADK 无法判断表结构版本）。
- **向量本体**：`data/vectors.db` 单表 `vector_items`，namespace 仅三种：`knowledge_chunks`（知识库切块）、`memory_items`（长期记忆）、`mcp_tools`（MCP 工具索引）。业务表中 `knowledge_chunks`/`memory_items`/`mcp_tool_embeddings` 只存正文或检索元数据，按 `ref_id` 与向量行对应。清数据按 namespace 同步清理，`mcp_tools` 保留。

## 易混淆与已废弃对象

- `models/` 目录下有 stale 的 **`investigation`、`plan` 编译缓存（`.pyc`）但无对应 `.py` 源码**——旧 `plan_executions`/`plan_steps`/`investigation_dispatches`/`investigation_worker_runs` 四表已由 `task_graph_runs`/`task_graph_nodes` 取代，历史不迁移，已废弃，不要以它们为准。
- **`channel.py` 仍存在**（对应 `published_channels`），非废弃；与会话分享 `share_tokens`、评测分享 `eval_share_tokens` 是三张独立表，勿混用。
- 状态枚举以源码注释/默认值为准，运行时可能扩展新值；建表/级联变更须回到对应 `models/*.py` 核对，不要凭本文臆断。
