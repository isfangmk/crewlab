# 常见故障排查（Runbook）

按症状查表；每条给出定位路径与处理动作。

## 后端起不来 / 端口被占用

1. 看 `logs/backend.log` 尾部报错。
2. 端口冲突（默认 18080）：找到占用进程后停止，或改 `PORT` 重启。
3. 用 `scripts/service.ps1 restart backend` 重启（会自动先停旧进程）。

## 进程的第一个问题很久才回答（后续正常）

- 一次性开销两笔：litellm 冷导入（约 10 秒）与远程模型价格表拉取超时（网络不通 GitHub 时约 10+ 秒）。
- 现已由启动期预热（日志可见「litellm 预热完成」）与 `LITELLM_LOCAL_MODEL_COST_MAP=True` 兜住；若仍复现，确认 `.env` 里该开关生效且预热日志已打出。
- 另：多步工具探查的问题本身要 3-4 轮 LLM 往返，每轮 2-3 秒属模型行为，非故障。

## 对话流式卡在「正在分析…」不结束

- 先看后端日志：若「观测回合结束」已打出，说明服务端回合早已完成，是浏览器端 SSE 消费停摆（嵌入式浏览器的 rAF 节流怪癖可导致此现象）。
- 处理：刷新页面即可恢复；消息与产出物均已落库，不会丢。

## query_knowledge / 上传知识库报嵌入不可用

- 症状：接口 5xx 或提示 EmbeddingServiceUnavailable / VectorStoreUnavailable。
- 检查 `EMBEDDING_BASE_URL`、`EMBEDDING_MODEL`、`EMBEDDING_API_KEY` 是否可用，`data/vectors.db` 是否可写。
- 上传仅支持 `.md / .txt / .pdf / .docx`；其他格式会 400。

## 沙盒执行失败（run_python 报错或 failed）

1. 工具卡「结果」里有 traceback：按 traceback 修数据或代码。
2. 无 traceback 且提示结果信封缺失：脚本被强制终止，查 `sandbox_executions` 表的 status/error 与超时配置 `SANDBOX_TIMEOUT_SECONDS`。
3. Docker 执行器排障：检查 `SANDBOX_DOCKER_HOST` 与镜像 `SANDBOX_IMAGE` 是否可拉取。

## 图表不渲染 / 显示原始 JSON

- 图表唯一生成通道是 `run_python` 的 `chart(data, 图型, 标题)` 助手，产出物在消息卡下方渲染。
- 正文里的 ECharts JSON 围栏不会被渲染成图（按普通代码块显示）。
- 配色与主题统一在前端 `web/src/lib/chartTheme.ts`；结构映射在 `backend/app/tools/chart_spec.py`。

## ask_user 澄清卡不出现 / 答案不回流

- 确认走的是根 Agent 直接对话（子 Agent 被委派时按假设继续，不会提问）。
- 检查审批页是否有 pending 记录；答案经 `POST /approvals/{id}/approve/stream` 回灌。

## 审计页动作是英文 / 缺条目

- 动作字符串存英文原始值，中文是展示层映射（`web/src/pages/Audit.tsx` 的 ACTION_LABELS）；历史行不迁移。
- 新增写操作端点时记得补审计与标签映射；消息发送按设计不进审计。
