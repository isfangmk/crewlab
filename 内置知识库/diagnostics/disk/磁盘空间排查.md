# 磁盘空间排查

磁盘告警的两类：**空间耗尽**与 **inode 耗尽**（空间还有但建不了文件）。两类的定位路径不同。

## 定位路径

```bash
df -h                  # 各挂载点空间使用率
df -i                  # inode 使用率（第二类故障看这里）
du -sh /var/log/*      # 逐层缩小到大目录
du -xh --max-depth=1 / # 只看本文件系统，避免跨挂载干扰
sort -rn               # 配合 du 找 TOP 大文件
```

按「挂载点 → 目录 → 文件」逐层下钻，`du` 与 `df` 差值大时优先查已删除未释放。

## 已删除但空间未释放

进程仍持有已删除文件的句柄时空间不会回收：

```bash
lsof +L1 | grep deleted   # 找持有已删除文件的进程
```

处理：重启/重载对应进程即释放；不要 kill 无关进程。

## 常见大头

| 来源 | 位置 | 处理 |
|---|---|---|
| 应用日志 | /var/log、应用 logs 目录 | 配 logrotate 或应用侧滚动，别直接删在写的文件 |
| journal 日志 | /var/log/journal | `journalctl --vacuum-size=500M` 限制总量 |
| 容器/镜像 | docker system df | `docker system prune`（确认无用后再清） |
| 临时文件 | /tmp、构建目录 | 确认无进程使用再删 |
| 上传/数据目录 | 业务数据目录 | 走业务归档，勿手工删库文件 |

## 清理纪律

- 删之前确认没有进程在写（尤其日志）；正在写的文件直接删会留下句柄占空间。
- 业务数据（数据库文件、上传目录）禁止手工删文件，走业务侧归档或清理接口。
- inode 耗尽多为小文件泛滥（缓存、session 文件）：`du` 找目录后按来源治理，别只删一部分了事。
